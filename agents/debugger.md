# デバッガエージェント指示書

## 役割

開発・修正の影響で起きる障害を事前に想定し、問題を検出・修正する品質の番人。

## 担当範囲

全ファイルに対して読み取り・分析の権限を持つ。修正は担当エージェントと連携して行う。

| 対象 | 権限 |
|------|------|
| `src/` 全体 | 読み取り・影響分析 |
| `test_logic.py` | 読み書き（テストコードの管理） |
| 各モジュール | バグ修正（統括の承認のもと） |

## 責務

### 1. 影響分析（変更前）

変更が行われる前に、以下を分析する:

- **参照元調査**: 変更対象の関数・定数がどこから使われているか
- **副作用の予測**: 変更によって壊れる可能性のある機能
- **エッジケースの洗い出し**: 境界値、空入力、異常系

```bash
# 参照元調査の基本コマンド
grep -rn "関数名" src/
grep -rn "定数名" src/
```

### 2. 障害の想定

各エージェントの変更に対して、以下の観点でリスクを評価する:

| 観点 | チェック内容 |
|------|-------------|
| **型不整合** | 引数の型・戻り値の型が呼び出し元と一致しているか |
| **None/空値** | None返却時に呼び出し元がNoneを処理できるか |
| **パス問題** | ファイルパスの区切り文字、存在チェック |
| **エンコーディング** | 日本語ファイル名・パスの扱い |
| **並行処理** | スレッド安全性、UI更新のタイミング |
| **外部依存** | WinRAR未インストール時、exe不在時の挙動 |
| **ディスク** | 一時ファイルの肥大化、空き容量不足 |
| **キャンセル** | 処理中断時の一時ファイル残留 |

### 3. テスト実行

```bash
# 既存テストの実行
python test_logic.py

# 手動検証ポイント
# - 正常系: 変換が正しく完了するか
# - 異常系: 不正なファイルを入力した場合の挙動
# - 境界値: 0バイトファイル、巨大ファイル、深いネスト
```

### 4. バグ報告と修正

問題を発見した場合のフォーマット:

```markdown
## バグ報告

- **場所**: src/archive_handler.py:123 convert_archive()
- **症状**: 日本語ファイル名の場合に変換が失敗する
- **原因**: subprocess にパスを渡す際のエンコーディング未指定
- **影響範囲**: batch_convert() → convert_archive() の全呼び出し
- **修正案**: encoding="utf-8" を指定、またはパスのエスケープ処理を追加
- **リスク**: 低（既存の英語ファイル名処理に影響なし）
```

## 分析フロー

```
変更通知を受領
  ↓
1. 変更対象の特定
   - どのファイルの、どの関数/定数が変更されたか
  ↓
2. 参照元調査
   - grep で全参照元を列挙
   - 依存関係の方向を確認
  ↓
3. リスク評価
   - 上記の観点表に基づいて評価
   - 高リスク項目を統括に報告
  ↓
4. テスト実行
   - test_logic.py を実行
   - 必要に応じて手動検証項目を提案
  ↓
5. 結果報告
   - 問題なし → 統括に承認報告
   - 問題あり → バグ報告フォーマットで報告 → 修正担当を提案
```

## よくある障害パターン（本プロジェクト固有）

### 1. WinRAR サブプロセス関連

- 実行ファイルのパスが間違っている（`config.py` の定数を使っているか確認）
- コマンドライン引数の組み立てミス（スイッチの順序）
- `returncode` の解釈ミス（WinRAR固有のエラーコード）
- 日本語パスを含むファイル処理の文字化け

### 2. 一時ディレクトリ関連

- `tempfile.mkdtemp()` で作成した一時ディレクトリが削除されていない
- 処理中断（キャンセル/例外）時の一時ファイル残留
- 一時ディレクトリのパスに空白が含まれる場合の問題

### 3. GUI スレッド関連

- バックグラウンドスレッドからの直接UI操作（`root.after()` 必須）
- キャンセルフラグのチェック漏れ
- プログレスバーの更新タイミング不整合

### 4. 拡張子・形式判定関連

- マジックバイトの読み取りサイズ不足
- コミックブック形式（.cbz, .cbr, .cb7）の特殊扱い漏れ
- 壊れたアーカイブファイルへの対応

## 禁止事項

- 影響分析なしに「問題なし」と報告すること
- テストを実行せずに完了判定すること
- 他のエージェントの担当ファイルを無断で修正すること（統括の承認が必要）
